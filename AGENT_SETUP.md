# Search agent and private conversation memory

The site chatbot uses the existing official LFM3-1.7B Q4_K_M model and
llama.cpp b11960 image pinned by digest in `compose.yaml`. Native function
calling is enabled with `--jinja`. Context is raised from 4096 to 8192 tokens;
reasoning remains off. Compatibility references:
https://huggingface.co/LiquidAI/LFM3-1.7B and
https://github.com/ggml-org/llama.cpp/blob/8642541b2/docs/function-calling.md .

## Request flow

The model sees the current question, recent user AND assistant messages, and a
short compressed conversation memory and an exact first-user-message anchor. The anchor prevents a lossy summary or ranked search result from redefining the start of the conversation. It chooses whether to answer or call:

- `search_site(query)`: query embedding using MiniLM, Qdrant cosine similarity,
  BM25 keyword ranking, reciprocal-rank fusion; five small passages per call.
- `search_memory(query)`: hybrid vector/keyword search over this session's
  stored message passages, with optional oldest/newest ordering and role filters chosen by the model. It also returns the exact first user question and chronological message numbers so similarity ranking is not mistaken for chronology. This archive is conversation data, not verified
  evidence about Tom.

The memory tool is offered only when there are older messages outside the configured recent-history tail. This avoids searching an empty archive; it does not select a topic or query.

The server appends native assistant tool calls and matching tool results and
asks the model again. It executes only the two named tools. No shell, external
browsing, write tools or keyword topic routes are exposed. Search argument
lengths, number of searches and prompt/output budgets remain bounded. No topic
is selected by Python keyword matching; BM25 remains one retrieval signal.
There is no deterministic category-answer shortcut or synthetic source score.

Published chunks are now about 100 lexical tokens (12 overlap) with preserved
article title, heading and URL; the current corpus produces 131 chunks. These
are lexical word counts, not the LFM tokenizer. MiniLM embeddings remain
unchanged. Context sizing uses llama.cpp `/apply-template` and `/tokenize`,
including tool schemas; reserve 960 tokens for output and template overhead.
When necessary, remove complete old conversational turns, never half a tool
exchange. The archive remains searchable after prompt trimming.

## Hierarchical memory

All completed exchanges are stored in server-side SQLite plus short passage
embeddings generated by the SAME MiniLM embedder. This small, private memory
index lives in SQLite, not the shared site Qdrant collection. Cosine similarity
and BM25 ranks are fused inside each session. No extra embedding service is
required.

When at least four unsummarized messages fall outside the most recent four
messages (two exchanges), LFM3 updates a rolling summary targeted under 120
words, capped at 192 generated tokens / 1200 characters. The original messages
remain searchable. Until a compaction batch is ready, one additional exchange
may remain verbatim. This is rolling summarization plus retrieval-based memory;
it is lossy and does not turn earlier assistant claims into verified facts.

Each browser receives an unpredictable 256-bit session cookie, HttpOnly,
Secure and SameSite=Strict. Only its SHA256 hash is stored as the session key.
Memory queries always use the server-derived session scope. API clients must
retain cookies; a fresh cookie starts a new conversation. Client-supplied
`history` is no longer used. Reloading keeps memory; Clear conversation calls
`POST /api/conversation/reset` to delete that session's data and rotate the
cookie. Clearing cookies alone abandons, rather than immediately deletes, the
old server session. There is no user login or cross-device memory.

Defaults: 40 completed user turns per session; seven-day inactivity expiry;
1000 stored sessions maximum. Expired/oldest records are purged on subsequent
memory access. SQLite secure deletion is enabled; database pages are reused.
One global model slot and existing per-IP minute/hour limits remain. Failed
answers do not become completed memory turns. Summary generation adds one
bounded model call during compaction. Compression controls prompt size, not
unlimited session/storage/inference cost.

Memory is persisted in Docker volume `site-chatbot_conversation-data`, mounted
at `/app/state`. Do not expose or commit the SQLite database, cookies, or
private chat transcripts. Normal operation does not log queries; optional
`AGENT_TRACE=1` is for local diagnostic runs only.

## Configuration and deployment

```bash
bash ops/download-model
docker compose -p site-chatbot config -q
docker compose -p site-chatbot up -d --build
curl --fail https://chat.srv1619516.hstgr.cloud/health
docker compose -p site-chatbot logs --tail 50 app llm
```

Compose fixes `LLM_CONTEXT_SIZE=8192` to match runtime `--ctx-size 8192`.
`RECENT_HISTORY_MESSAGES=4` controls the verbatim tail (even values, 2–12).
`STATE_DIR=/app/state`, `MAX_AGENT_SEARCHES=3`, `MAX_SESSION_TURNS=40`, and
`MEMORY_TTL_DAYS=7` configure memory and loop bounds. Final output is capped at
640 model tokens. The search/generation loop has a 240-second deadline (plus
bounded pre-loop summary generation and storage work); errors are explicit.
The inference memory cap remains 2500 MiB, app 768 MiB and Qdrant 512 MiB.

SSE emits `status`, text `delta`, `final`, `done` or `error`. Native tool calls
and reasoning are never forwarded as text. Citation numbers are issued from
retrieved passages per answer and verified before saving the final answer.
Historical citation markers are removed from assistant context; an invalid
citation gets one model-driven correction opportunity within the same search
and time budget.
This checks citation existence, not semantic entailment. Streamed text remains
provisional until `final`; an invalid citation becomes a visible error.

Tests: `python3 -m unittest discover -s tests -v`, `node --check static/app.js`,
and Compose configuration validation. The former keyword-route unit tests
were replaced with agent/memory behavior tests. Historical benchmark outputs
remain preserved; those scores do not describe this new architecture.

Changing the embedding model requires rebuilding archived memory embeddings or
clearing conversation memory; changing vector dimensions produces a clear error.
The current embedding model remains MiniLM.

Deployment source is currently local. These changes have not been committed or
pushed to GitHub; deploying the unchanged upstream main would restore the old
pipeline. Review and publish the source changes before using the existing
automated main-branch deployment hook.
